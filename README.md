# 鹿丰 · 单作者风格画像与仿写自检工具链

> 从**工作室型公众号**（一人在主号发稿、同时收录多校师生同题作品）的抓取文本里，
> 按**署名行**切出单一作者的干净语料，算出他的语言分布，并对「像不像他」做程序化自检。
>
> 仓库内的示例作者代号为 `lf`，画像与词表均已脱敏。
> **本仓库不包含任何原文**——它发布的是方法。语料请自备。

---

## 一、它解决什么问题

做风格研究时，最容易犯的三个错，这套工具各有一个对应的解法：

**① 把"收录件"当成作者本人的字。**
工作室型公众号里，一篇文章常常夹着多校师生的同题作品、学术转载、机构新闻卡片。
拿全量文本去统计，算出来的是**这个号的**特征，不是**这个人的**。
→ 解法：按**署名行**切分。署名行高度规整，可以程序化切，而且切完还能逐段复核。

**② 用一个平均值描述一个多面作者。**
同一个人的下水议论文和叙事散文，段末反问率是 **40.7% vs 1.4%**——差 29 倍。
把两者混合求平均，得到的那个数**谁也不是**。
→ 解法：**分目别类**（文体 × 栏目 × 题材 × 篇幅），每个子类各自取阈值。

**③ 把"我没见过"当成"他不用"。**
实测过两次：一次是某个词在样本里出现 0 次就被判为"他不用"，而它在全量里覆盖 2.5%——
用这个假规律一次误杀了两篇真文。
→ 解法：**稀有 ≠ 非他**。凡"否定性硬指标"，一律回全量核验再采信。

## 二、方法概要

四步管线，每一步都有脚本：

| 步 | 做什么 | 脚本 |
|---|---|---|
| **① 切分** | 按署名行（`单位 + 姓名`）从抓取文本里切出目标作者段落 | `extract_own_corpus.py` |
| **② 清洗** | R1–R8 规则剥掉不属于他的字：图片名、他人署名、栏目标题、评点夹批、总评块 | `clean_own_corpus.py` |
| **③ 复核** | 分段打风险旗标 → 逐段判「确证／存疑／排除」→ 查重去重 | `review_own_corpus.py`、`dedupe_corpus.py`、`aggregate_corpus.py` |
| **④ 画像** | 分目别类算分布 → 写入 profile，供自检器读阈值 | `make_profile.py`、`strata_stats.py` |

题目进来之后，先出一张**施工单**再动笔：

| 脚本 | 出什么 |
|---|---|
| **`analyze_topic.py`** | 题材归属（决定用哪列阈值）／可比篇目与相似度天花板／结构类型／素材池与标题建议 |

> **为什么需要它**：原来的流程写着"定题 → 确认"，暗含的假设是"题目从作者自己的题库里挑"。
> 用户给一道外部题时，该按哪一列阈值写、他写过多少接近的题、用哪种结构，全都没判，只能靠事后自检去补。
> 实测两个坑：**题面往往不含任何题材词**（古语类必然如此，靠题型推断兜底）；
> **题眼常落在引号里**（`'输与赢'`），第一版把引号当标点洗掉，只剩「理解」这类套话。

写稿之后，五套自检器逐项核对：

| 脚本 | 查什么 |
|---|---|
| `check_draft.py` | 13 项结构指标（句长、段落节奏、标点密度、篇末反问、素材名单…） |
| `check_flaws2.py` | 例证段收口率、段长起伏（变异系数）、贴标签起句、标点密度 |
| `check_verbosity.py` | 句长均值、长句占比、冗余度、政策词密度 |
| `check_flaws.py` | 感叹号、叠字、口语词 |
| **`check_title.py`** | **标题长度与结构类型，多篇时还查「类型分散度」** |
| **`check_politics.py`** | **列出政治类素材，并把未核过的引语与数字标出来（核验清单，不是禁写检查）** |

> **标题单独列一项**，因为它最容易漏：标题在稿件第一行，程序化读正文时会被当"元信息"跳过。
> 实测后果是三篇仿稿的标题全落进同一个类型（占真值 18.8%），而作者占比最高的两种
> （冒号式 41.0% / 单句 37.6%）一次没用。**越显眼的位置，越不能有规律性。**

## 三、快速开始

需要 **Python 3.8+**，**纯标准库，零外部依赖**。

```bash
# 1. 自检一篇稿（不需要语料，直接用 profile 里的阈值）
python scripts/check_draft.py 我的稿子.md

# 2. 若要在自己的语料上重新统计（需要先准备好语料目录）
export STYLE_PROJECT=/path/to/your/project    # Windows: set STYLE_PROJECT=D:\path\to\project
python scripts/make_profile.py --md
```

`profile_io.py` 的查找顺序：
- 项目根：`STYLE_PROJECT` → 脚本上一级 → 当前目录
- 画像：`STYLE_PROFILE` → `scripts/profile/` → `scripts/../profile/` → `$STYLE_PROJECT/profile/`

## 四、换一个作者

这套流程不绑定作者，只绑定**版式**（见第六节）。换成别人要改的东西：

| 改什么 | 在哪 |
|---|---|
| 署名行切分的目标姓名 | `scripts/extract_own_corpus.py` 的 `NAME` |
| 画像统计的目标姓名 | `scripts/make_profile.py` 的 `NAME_RE` |
| 素材名单、题材关键词、口语词表、指纹串 | `profile/lf.json` 的 `wordlists` |
| 目标子类（文体／题材／字数段） | `profile/lf.json` 的 `subclass`、`make_profile.py` 的 `GENRE` |
| 目标区间 | 跑 `make_profile.py` 自动刷新；标了 `source: manual` 的会被保留 |

改完跑一次 `make_profile.py`，阈值就换成新作者的实测值了。

## 五、边界：请务必读完

**这不只是一个技术问题。**

1. **不得用于冒充他人发表。**
   用本工具生成、再挂上他人署名行的文本，踩《民法典》第 1012 条（假冒姓名）。
   本仓库已刻意**排除了**生成带署名包装版的两个脚本——那是有意为之，不是遗漏。
2. **AI 生成内容须标识。**
   依《人工智能生成合成内容标识办法》，AI 生成的内容对外发布时应当标明。
   如果你做的是风格仿写实验，产物首行请写明"AI 仿写实验产物"。
3. **语料版权归原作者。**
   本仓库不含任何原文。你自行抓取的语料，复制、转载、发布的边界由你自己负责——
   公开署名的单篇文章受著作权保护，整篇复制进公开仓库属于转载，不是合理使用。
4. **政治／党史／政策／楷模类素材可以用，但引语与具体数据必须可核。**
   这几类覆盖示例语料 **42.4%** 的篇目，是中文议论文的常态，回避它们等于白丢一块相似度。
   **风险不在"用了"，在"编造或记错"**——所以规则是"用 + 核验"，不是"禁"：
   领袖原话引用、一切具体数字、政策专名**用前必须核实**；
   编造领袖言论或官方文件表述、对政策的评价性议论**仍然不写**。
   工具里有 `scripts/check_politics.py` 出核验清单，核过的记进 `profile.politics.verified`。
5. **n = 1。** 这套流程只在一个作者、一个账号上完整验证过。
   它依赖该号有稳定的**栏目录层**和**多校合集的署名行版式**（见下）。

## 六、适用前提（不满足就别用）

| 前提 | 说明 |
|---|---|
| 版式 | 该号是**工作室型合集**：多校师生同题共写，署名行独立成行 |
| 栏目 | 有足够的栏目录层（考后号外／前文后赏／同题共写 之类）才能分目别类 |
| 体量 | 同一作者的段落最好 **≥100 段**，否则子类统计没有意义 |

反例：**"一人一号、篇篇独发、从不收录他人"**的作者——署名行切分这条通道直接失效
（因为整号都是他的，不需要切分，也不存在"收录件污染"这个问题）。

## 七、目录

```

  ├─ 语料管线    extract → review → clean → dump_batches → aggregate → dedupe
  ├─ 题目        analyze_topic（题目施工单）
  ├─ 画像        make_profile / strata_stats / strata_extra / structure_stats
  │              critique_stats / column_stats / fingerprint / profile_io
  ├─ 自检        check_draft / check_flaws / check_flaws2 / check_verbosity
  │              check_title + 标题画像 title_stats / check_politics
  └─ 盲测        build_blindtest_naive / build_expert_test / pick_controls / tally_human_scores
profile/
  ├─ lf.json   机器读：targets / baselines / wordlists / truth / caliber / rules
  └─ lf.md     人读
docs/
  ├─ methodology.md   方法论的可迁移发现（五个，含踩过的坑）
  ├─ pitfalls.md      应试下水文的四类常见论证缺陷（通用清单）
  └─ portability.md   可移植性说明
```

## 八、已知失败档

**对外必须承认，不省略。**

| # | 欠账 | 实证 |
|---|---|---|
| 1 | **没能骗过行家** | 把仿稿混进真文让专业读者盲判，仍能识别。理由高度一致：「太顺、太齐、太干净」 |
| 2 | 冗余度只到子类中位的 3–4 成 | 追这个指标五次全失败；事后发现它与判读结果**不相关甚至负相关**，已不再作为目标 |
| 3 | 口语词、叠字偏少 | 明显低于子类中位 |
| 4 | ~~政治素材不仿~~ **已放开** | 原为主动放弃（欠账 28.8% 篇目）；2026-09-24 改为"用 + 核验"，见第五节 |
| 5 | 正式规模的盲测未跑 | 只到单篇校准与 8 篇小样本 |

**已兑现的部分**：13 项结构自检可稳定达标；标点层在修正口径后全部落带内；
已能骗过不熟悉该作者的普通读者。

> 失败档里最有价值的一条是 #2：**它是一次"追错指标"的完整记录**。
> 详见 `docs/methodology.md`。
