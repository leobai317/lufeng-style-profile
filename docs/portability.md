# 可移植性说明

> 结论先行：**自检工具在任何设备上都能独立运行；生成环节需要自备语料。**
> 验证方式：把整个仓库复制到新目录、清空环境变量、在无语料的路径下运行。

---

## 一、能力分层

「能不能通用」其实是三件不同的事，要分开回答：

| 层 | 问题 | 需要什么 | 新设备可用？ |
|---|---|---|---|
| 1 **被发现** | agent 能不能找到这个 skill | `SKILL.md`（标准 frontmatter） | ✅ 手工复制目录即可 |
| 2 **能自检** | 拿到一篇稿，能不能判它像不像 | `scripts/` + `profile/` | ✅ **已实测** |
| 3 **能生成** | 从零写一篇像他的稿 | 画像 **＋ 该作者的真实文本** | ⚠️ 需自备语料 |

### 为什么"能生成"需要语料

**`profile/lf.json` 里没有任何一段原文**——它是数值、词表、区间。
所以：

> 画像知道他的**数值形状**，但没**见过他写的字**。

流程里「取 3–5 篇同文体真文对照」（few-shot）那一步要读语料目录。
语料不在时，生成会从「照着真文写」退化成「照着阈值表写」——
**阈值能保证指标像，保证不了手感像。**

这是**有意为之**：本仓库不发布任何受版权保护的原文。
正确用法是**把提取器带走，而不是把文本带走**——
拿你自己的抓取跑一遍 `extract → clean → aggregate → make_profile`，
就能生成你自己的画像。

## 二、哪些脚本脱离语料可用

| 脚本 | 脱离原项目 |
|---|---|
| `check_draft.py` | ✅ 13 项指标全部读 profile，不碰语料 |
| `check_flaws2.py` | ✅ 找不到语料时自动切到 **profile 基线模式**并打印说明 |
| `check_verbosity.py` | ✅ 同上 |
| `check_flaws.py` | ✅ 同上 |
| `extract_own_corpus.py` 等 6 个语料管线脚本 | ❌ 需要抓取目录（职责所在） |
| `make_profile.py` / `strata_stats.py` / `strata_extra.py` | ❌ 需要 `corpus_own/_final.json`（"重新算阈值"） |
| `build_expert_test.py` 等盲测脚本 | ❌ 需要语料挑对照真文 |

**关键区别是"读阈值"和"算阈值"**：
统计口径已经抽到 `profile/lf.json` 的 `truth` / `baselines` 里，所以**读**不依赖语料；
依赖语料的是**重新算**。

## 三、静态检查

| 项 | 结果 |
|---|---|
| 硬编码绝对路径（盘符 / `/Users/`） | **无** ✓ |
| Windows 专有 API（`os.startfile` / `winreg` / `shell=True`） | **无** ✓ |

| 外部依赖 | **纯 Python 标准库** ✓ |

## 四、边界用例

三个自检器在以下输入上都不崩（`rc=0` 正常 / `rc=2` 稿件不合规并给出可读提示）：

| 用例 | check_draft | check_flaws2 | check_verbosity |
|---|---|---|---|
| 正常稿件 | 0 | 0 | 0 |
| 有段落但无人物素材 | 0 | 0 | 0 |
| 极短（无 ≥25 字段落） | 0 | 2 | 0 |
| 只有标题行 | 2 | 2 | 0 |
| 不存在的文件 | 2 | 2 | 2 |

**退出码约定**：`0` 正常 · `2` 稿件不合规（已给可读提示）· 其他 = 真异常。

（这些边界是补测出来的。原先的版本在这三种输入上会直接抛异常：
无人物素材时 `None < float`、无长段落时除零、路径不存在时 `FileNotFoundError`。）

## 五、迁移步骤

```
1. 复制整个仓库目录到新设备
2. 确认 python3 可用（需要 3.8+，用了 f-string 与 statistics）
3. 自检：  python scripts/check_draft.py <稿件.md>
   —— 不需要任何环境变量；找不到项目时自动用 profile 基线
4. 要重新统计：export STYLE_PROJECT=<项目路径>，或把语料放在 scripts/ 的上一级
```

**解析顺序**
- 项目根：`STYLE_PROJECT` → 脚本上一级 → 当前工作目录
- 画像：`STYLE_PROFILE` → `scripts/profile/` → `scripts/../profile/` → `$STYLE_PROJECT/profile/`
